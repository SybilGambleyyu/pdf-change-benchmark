# Validation approach

The suite rebuilds the entire fixture tree into an empty temporary directory
and compares every generated byte and truth record with the packaged copy. It
validates manifest ordering and fixture membership, rejects malformed truth,
and invokes a supplied PDFFence executable through its public JSON CLI.

The PDFFence adapter is intentionally process-bound. It does not import
PDFFence internal modules, so changes to the CLI report contract are visible as
benchmark failures.

## Initial integration evidence

On 2026-08-06, PDFCAB 0.1 scored the public PDFFence source candidate at
commit 771b3a50ccf745658fe2a65d52332a443e997df1 through its installed command
line executable. It passed all 14 of 14 fixture pairs, including a same-count
JavaScript payload rewrite that remains review-visible only as stored-byte
change. A release verification will repeat this check against a public release
artifact rather than a source checkout.
